# 디벨로켓 교안 도우미

AI 기반 게임 기획 교안 자동 생성 도구

## 실행 방법

### 사전 준비
- [Node.js](https://nodejs.org) 설치 (LTS 권장)

### 실행
1. `실행.bat` 더블클릭
2. 브라우저가 자동으로 열립니다 (`http://localhost:3000`)

> 종료: 명령 프롬프트 창을 닫거나 `Ctrl+C`

### API 키
화면의 설정(톱니바퀴)에 넣습니다. 키는 이 브라우저에만 저장됩니다.
- **Gemini**: 교안 생성, 이미지 생성과 판독 ([Google AI Studio](https://aistudio.google.com/app/apikey)에서 발급)
- **Claude**: 교안 생성, 교차 검수 ([Claude Console](https://console.anthropic.com)에서 발급)
- **Google Custom Search** (선택): 본문 이미지 웹 검색. [검색 엔진](https://programmablesearchengine.google.com/controlpanel/all)을 만들어 CX를 넣고, [Google Cloud Console](https://console.cloud.google.com/)에서 Custom Search API 키를 발급합니다. 키를 쉼표로 여러 개 넣으면 한도에 걸릴 때 돌려 씁니다.
- **Pixabay** (선택): 웹 검색이 실패할 때 쓰는 무료 스톡 이미지 ([API 문서](https://pixabay.com/api/docs/)에서 발급)
- **Higgsfield** (선택): 이미지 생성 모델에서 Higgsfield를 고르면 교안 삽화를 Higgsfield로 만듭니다. [Higgsfield Console](https://console.higgsfield.ai)에서 API 키(Key ID:Secret)를 만들고 API 잔액을 충전합니다.
  - Higgsfield API는 브라우저에서 직접 부르는 것을 막으므로, 처음 한 번 [Cloudflare Worker](https://dash.cloudflare.com) 중계를 배포합니다 (무료 등급으로 충분).
  - 설정의 "중계 코드 복사" → Cloudflare 대시보드 Workers & Pages → Create → Worker → Deploy → Edit code에 붙여 넣고 Deploy → 나온 주소(`https://이름.계정.workers.dev`)를 설정의 중계 주소에 넣고 "연결 확인"
  - 중계는 키를 저장하지 않고 이 앱 주소에서 온 요청만 Higgsfield로 넘깁니다. 다른 주소에서 앱을 쓰면 Worker 변수 `ALLOWED_ORIGINS`에 그 주소를 적습니다. 코드: `relay/higgsfield-relay.mjs`

## 주요 기능

- **AI 교안 생성**: Google Gemini API · Claude API 기반 자동 교안 생성 (키는 설정 패널에서 입력, Gemini 키가 없으면 삽화는 SVG로 생성)
- **5탭 시스템**: 기본학습 / 기본실습 / 심화학습 / 심화실습 / 학습이해도
- **내보내기**: Markdown / HTML / PDF / PPTX / ZIP. 현재 차시는 전체 탭(5개 탭을 한 문서로)과 지금 탭 중에서 고르고, HTML·PDF는 화면과 같은 렌더와 서식(그림·인용 막대·번호 목록·다이어그램)으로 나감. 현재 교과는 문서 하나로(PDF에서 차시마다 새 쪽). PDF는 새 창 없이 인쇄 창을 열어 'PDF로 저장'. ZIP의 차시 폴더마다 교안.html(그림 포함)이 들어감. 교수안(강사뷰)도 MD 옆에 HTML·PDF 내려받기
- **이미지 삽입**: Google 검색 + Pixabay + AI 생성 자동 삽입. 설정의 '교안 이미지 양'으로 태그마다 / ## 섹션마다 한 장 / 넣지 않음을 고르고, 남긴 자리는 '일괄 이미지 찾기'로 탭마다 채움
- **교수안(강사뷰)**: 교안을 바탕으로 강사 활동·설명 내용·멘트 예시·학생 활동을 담은 교수안 생성
- **슬라이드**: 교수안과 함께 만든 슬라이드 편성안을 슬라이드 스튜디오에서 편집하고 PPTX·HTML·PDF로 내보내기
- **편성안 수정**: 슬라이드 편성안 MD를 고쳐 슬라이드를 다시 만들기
- **슬라이드 형식**: 프레젠테이션용과 상세 교재형 중 골라 생성
- **슬라이드 이미지 자동 생성**: 장수를 정해 생성할 때 이미지를 함께 만들고, 내용이 맞는 교안 이미지는 재사용
- **참고 이미지**: 차시별로 여러 장 모아 슬라이드 이미지 칸에서 고르고 교수안 끝에 싣기
- **HTML 불러오기**: 내보낸 슬라이드 HTML에 내장된 교수안·편성안·참고 이미지까지 되살려 이어서 편집. 크기 상한 없이 조각으로 읽고 그림을 떼어 둔 글로 슬라이드를 읽은 뒤 그림을 되돌림(import-stream.js. 불러올 수 없는 HTML은 콘솔에 경고로만 남김)
- **완성 MD 변환**: 교수안.md·슬라이드 편성안.md를 올려 AI 없이 문서와 슬라이드 만들기(64MB 상한 없이 조각으로 읽음, 박힌 그림은 그림 목록으로 옮김)
- **출력 샘플**: 교수안·슬라이드 편성안 샘플 미리보기와 내려받기
- **과정 설계**: 주제와 단원 목록에서 시간을 배분하고 학습모듈 블록으로 나누어 교과·차시 생성, 블록·진행 단계·과정 목표 편집, 차시 구성 미리보기, 과정 공통 사용 툴, 과정 설계서 내려받기
- **전체 생성**: 빈 항목을 교안 5탭, NCS 요소, 교수안·슬라이드, 문제은행 순서로 (남은 차시 생성 창에서 켜면 SVG 삽화도) 만들기. 화면을 막지 않아 생성 중에도 끝난 항목을 읽을 수 있고, 실패한 항목은 건너뛰고 마지막에 알림
- **긴 작업 진행 막대**: 탭 하나 만들기·탭 전체 AI 수정·탭 모두 다시 만들기·일괄 이미지 찾기·콘텐츠 정리도 화면을 막지 않고 오른쪽 아래 막대에 단계, 걸린 시간, 이미지 장수와 남은 시간, 중지 버튼을 보임. 끝나면 알림(다른 창을 보고 있으면 브라우저 탭 제목에도 표시). 이미지 단계에서 중지하면 그리던 그림 호출도 끊고, 남은 그림 자리는 두어 이어서 만들 수 있음
- **항목 탐색줄**: 교안 탭, 교수안, 슬라이드, 문제은행을 한 줄에서 오가며 본문 자리에서 보기, 생성 중인 항목 표시
- **교육 자료 양식**: 교안을 학습자용 직무 교육 자료 양식 MD로 내려받기 (차시·교과·과정 단위, 저장된 교안은 그대로)
- **남은 차시 일괄 생성**: 교과 또는 과정 전체에서 비어 있는 탭만 차례로 생성하고 교수안·슬라이드 편성안까지 함께 만들기 선택, 실패한 차시는 한 번 재시도 후 건너뛰고 보고, 받고 있는 단락까지만 저장하고 중지
- **기존 내용 보강**: 예전에 만든 교과와 차시에 NCS 자동 배정과 삽화를 채우기 (확정한 항목은 유지)
- **교과 현황**: 과정 시간 막대, 교과별 시간 비율과 교수안·NCS·문항·완료 배지, 목표 시간에 비율대로 맞추기
- **차시 구성**: 교과의 차시 제목과 시간을 한 화면에서 고치기
- **생성 옵션**: 학습 목표 수, 학습자 수준, 섹션당 분량을 과정 기본값과 차시별로 지정
- **블록 다시 설계**: 추가한 교과의 차시를 AI로 다시 나누고 이전 차시는 휴지통으로 이동
- **차시 시간 변경**: 차시 카드에서 시간을 바꾸면 진행 단계 시간도 함께 조정
- **교수안·편성안 묶음**: 교과의 교수안과 슬라이드 편성안을 한 파일로 내려받기, ZIP 내보내기에도 포함
- **학습 목표 세트**: 학습 목표·내용 섹션·체크리스트를 한 벌로 AI 추가·삭제, 문항 연결 번호도 함께 수정
- **컨벤션 검수**: 콘텐츠 업무 설계 규칙으로 교안 자동 검사. 버튼에 필수·권장 지적 수를 표시하고 패널에서 지적과 규칙 목록 확인
- **AI 수정 제안**: 검수 지적이 있는 섹션만 고친 수정안을 미리 보고 반영 (고정 섹션 제외)
- **생성 직후 자동 수정**: 탭과 교안 전체 생성 뒤 필수 지적이 남으면 한 번 고쳐 받아 나아졌을 때만 교체
- **수동 검수 기록**: 사람이 확인할 항목을 차시·탭별로 체크하고 확인 시각 저장, 내용이 바뀌면 다시 확인하도록 표시
- **변경 미리보기**: 탭 재생성, 탭 전체 AI 수정, AI 수정 제안을 섹션별로 골라 반영, 검수 지적 수 변화 표시 (탭 재생성은 새 글에 없는 이전 섹션을 기본으로 지우고 이전 글은 작업 기록에 보관)
- **드래그 서식 막대**: 교안 본문을 드래그하면 슬랙과 같은 순서의 막대(굵게·기울임·밑줄·취소선, 문단 스타일, 링크, 번호·글머리 목록, 인용, 코드, 코드 블록, 구분선)가 뜨고, 누르면 저장된 마크다운에 바로 반영. 이미 그 서식이면 다시 눌러 풂(문단 전체가 굵은 "라벨: 설명"에서 설명만 골라 풀기 포함). Ctrl+B/I/U·Ctrl+Shift+X, Ctrl+Z로 되돌리기. 고른 번호 목록만 번호로 그림
- **단락 수정**: 본문을 두 번 누르면 그 단락만 원문 편집 상자로 열림(Enter 저장, Shift+Enter 줄바꿈, Esc 취소, Ctrl+Z 되돌리기). 화면 블록과 원문 블록을 글자로 짝지어 후처리로 블록이 나뉘어도 누른 단락이 열림. 위쪽 보기/수정 버튼은 없애고 탭 전체 원문 편집은 도구 → 원문 전체 수정으로 옮김. 교안 위 안내 줄(✕로 닫으면 다시 안 보임)과 단락에 마우스를 올리면 나오는 점선으로 고치는 방법을 알림
- **마크다운 서식 도구**: 원문 전체 수정의 서식 버튼, Ctrl+B/I/K, 목록 이어 쓰기, 나란히 보기, 보기로 돌아가기
- **탭 복사·빠른 지시·생성 중단**: 탭 마크다운 복사, AI 수정 빠른 지시, 받은 단락까지 저장하고 멈추는 중단 버튼과 수신 글자 수, 교안 전체 생성과 교수안 생성도 중지 가능
- **안전한 표시**: 교안에 든 스크립트와 이벤트 속성을 화면과 내보낸 HTML에서 제거, 더블클릭 편집은 보고 있는 탭에 저장, 다른 브라우저 탭에서 과정이 바뀌면 경고
- **NCS**: 교과별 능력단위 자동 배정·AI 추천·검색·확정, 차시별 능력단위요소 등록·추천, 교수안 개요에 표시 (NCS 29차 체계 2,156개)
- **NCS 요소 자동 배정**: 적합도 순으로 능력단위요소를 미확정 배정하고, 요소가 없으면 능력단위 수준으로 추천하며 목록 밖 후보를 표시
- **빈 차시 없음**: 적합도 기준을 넘는 후보가 없어도 가장 가까운 후보를 배정하고, 교안이 없거나 AI를 쓸 수 없는 차시는 제목과 학습 목표로 찾은 코드를 확정 전으로 넣은 뒤 교안을 만들면 AI로 다시 배정 (모두 해제한 차시는 비워 둠)
- **차시 카드 NCS 팝업**: 카드의 NCS 코드에 마우스를 올리면 후보 코드별 요소·능력단위·수준·근거와 적합도 점수(AI 적합도 / 키워드 일치도)를 보여 주고, 골라서 바로 확정하거나 다른 코드로 바꿈 (클릭하면 고정, Esc·바깥 클릭으로 닫기)
- **정리된 사이드바**: 차시가 있으면 차시 목차 만들기(주제·참고자료·차시 수·어투)를 접고, 교과 NCS·교과 일괄 작업·교과 정보는 요약과 바로 쓰는 버튼만 보이는 머리줄로 접음 (접힘 상태는 브라우저에 기억). 차시 카드는 번호·코드·제목·설명 한 줄·상태 칩만 보이고, 교안 생성은 늘 보이며 MD 올리기·순서 변경·삭제는 카드에 마우스를 올리면 나타남
- **판서 영상**: 차시 도구의 '판서 영상'을 누르면 그 차시 교안(탭마다 `#` 장, 그림 제외)과 제목을 [화이트보드 교안 스튜디오](https://rkdghkclgns-design.github.io/whiteboard-studio-web/)로 넘겨 새 탭에 엶. 스튜디오는 주제와 대상 학습자(대학생·성인)를 채우고 자료 기반 생성을 켠 뒤 이 교안만 자료로 고르며, 나레이션·판서 영상 생성은 스튜디오에서 직접 누름. 두 사이트가 같은 GitHub Pages 주소라 브라우저 저장소로만 전달(서버 없음, 10분 안에 한 번). 다른 주소에서 연 Teacher는 교안 파일을 내려받아 스튜디오 지식 보관함에 넣도록 안내
- **판서 영상 내용 직접 쓰기**: 넘기기 전에 '판서 영상 만들기' 창이 열려 주제와 담을 내용(차시 교안 또는 그림이 든 절의 글로 미리 채움)을 고쳐 쓰거나 새로 써넣을 수 있음. 스튜디오는 이 내용만 자료로 씀
- **그림을 판서 영상으로 바꾸기**: 보기 화면에서 교안 그림에 마우스를 올리면 '판서 영상으로 바꾸기'. 그 그림이 든 절(가장 가까운 위 제목부터, `■ 소제목` 줄 포함)의 글로 창이 열리고, 스튜디오에서 영상을 만든 뒤 'Teacher로 보내기'를 누르면 Teacher 탭으로 돌아왔을 때 그 그림 자리가 영상으로 바뀜. 원래 그림은 영상 표지로 남고 '원래 그림으로'로 되돌림. 교안 글은 바뀌지 않아 PDF·슬라이드·MD·ZIP 내보내기에는 원래 그림이 나가고, 현재 차시 HTML 내보내기에는 영상이 파일 안에 들어감. 영상은 이 브라우저(IndexedDB)에만 저장되어 다른 PC에서는 원래 그림으로 보임
- **화면으로 따라 하는 사용 가이드**: 처음 방문하면 열리는 가이드 창. 왼쪽 '작업별 바로가기'(14단계: 화면 둘러보기·API 키·모델과 이미지·교과·차시 목차·차시 카드·교안 생성·교안 고치기·도구 메뉴·판서 영상·그림 → 판서 영상·교수안과 슬라이드·교과 일괄 작업·내보내기와 백업), 오른쪽 진행 막대·제목·설명, 예시 데이터로 찍은 실제 화면 캡처에 번호와 테두리, 같은 번호의 설명과 알아 두면 좋은 점. 설명에 마우스를 올리면 캡처 속 같은 번호가 강조되고, '화면 확대'로 크게 봄. ← → 키로 넘기고, '나중에 보기'(Esc)는 다음 방문에 다시, 닫기(✕)나 완료는 다음부터 열지 않음. 오른쪽 위 '사용 가이드' 버튼(또는 설정 → 사용 가이드 보기)으로 언제든 다시 열기
  - 캡처와 번호 위치는 `scripts/capture-guide.js`가 만든다(빈 브라우저로 앱을 열면 나오는 예시 과정을 1280×800으로 찍고, 번호 붙일 요소 위치를 % 로 재서 `js/guide-shots.js`에 적음). 화면이 바뀌면 `PLAYWRIGHT=<playwright 경로> node scripts/capture-guide.js`(한 장만: 뒤에 캡처 이름)로 다시 찍는다
- **항목에 딸린 '용어: 설명' 문단**: "• 핵심 역할" 같은 목록 다음에 오는 "**전투 설계**: 설명" 문단(또는 둘 이상 이어진 그런 문단)은 왼쪽 회색 막대로 이어 들여 써서 그 항목에 딸린 인용처럼 보임. 화면 블록 수는 그대로라 두 번 눌러 고치기가 그대로 맞고, PDF·HTML 내보내기에도 같게 나감
- **NCS 요소 직접 찾기**: 차시 정보에서 코드·능력단위·요소 이름으로 찾아 바로 고르기
- **일괄 덮어쓰기**: 남은 차시 생성 창에서 이미 만든 내용도 모두 다시 만들기. 지우기 직전에 내용이 있는 차시를 통째로(글·그림·교수안·슬라이드 화면 편집·삽화) 휴지통에 넣어 30일 동안 되살릴 수 있음(작업 기록 칸을 쓰지 않고, 휴지통의 '지운 차시 100개' 상한에도 세지 않음). 되살리면 다시 만든 차시 바로 아래에 새 id로 생김. 사본과 다시 만든 차시는 같은 판서 영상 파일을 가리키므로, 한쪽에서 '원래 그림으로' 되돌리거나 새 영상으로 바꿔도 다른 차시·휴지통 항목이 쓰는 영상 파일은 지우지 않음
- **과정 설계 편집**: 미리보기에서 단원명을 고치고 블록을 추가·삭제
- **차시 하나 받기·편성안 보기**: 1시간 차시 하나의 교수안·편성안 내려받기, 편성안을 문서로 읽기
- **참고 파일**: AI 수정 입력줄의 클립으로 파일을 붙이면 그 차시의 AI 수정과 교안 생성에 반영
- **AI 수정 입구 하나**: 아래 명령줄에 요청을 쓰면 글을 골랐을 때는 그 부분만, 고르지 않았을 때는 이 탭 전체를 고침(탭 전체는 바뀐 섹션을 미리 보고 골라 반영). 드래그 막대의 'AI로 수정'은 고른 글을 이 명령줄로 넘김. 교수안·슬라이드·문제은행을 볼 때는 명령줄과 안내 줄을 숨김
- **역할별 AI 분배**: 설정에서 켜고 Gemini·Claude 키가 모두 있으면 구조·본문·검수는 Claude, 슬라이드·요약·문항은 Gemini가 맡고 교차 판단은 항상 다른 공급자가 함
- **NCS 참조 목록**: 등록한 능력단위와 요소를 보고 고치며 검증 상태 표시
- **1차시 분할**: 수업을 60분 단위로 나눈 차시 구성표, 학습 목표·개요·흐름·평가·유의사항을 갖춘 차시별 교수안, 차시마다 표지·목차·학습목표·체크리스트·마무리를 갖춘 편성안 내려받기, 슬라이드 스튜디오에서 한 차시만 따로 열기
- **차시 관리**: 카테고리, 작업 상태, 사용 툴·버전, 선행 차시, 변경 이력, 상태·검색 필터
- **차시 목록**: 카테고리별 묶음, NCS 필터, 필수 위반·문항 수 배지, 제목 중복 확인, 카테고리 이름 변경·삭제, 교과 간 이동, 휴지통 30일 보관
- **처음 쓰는 사람이 바로 성공하게**:
  - 처음 기본값은 Gemini Flash·추론 보통·핵심 그림만(이미 고른 설정은 그대로). 글은 무료 키로도 되지만 기본 그림 모델 Nano Banana 2.1은 무료 키로 못 쓸 수 있음. 그때는 빠르고 저렴하게를 누르면 글 모델이 SVG로 그림

  - 교과 삭제도 휴지통으로(교과 목록 아래 휴지통에서 30일 동안 복원. 교과는 30개까지 두고, 넘치면 오래된 것부터 완전히 지우며 그 수를 알림)
  - 교과 백업 ZIP에 복원용 데이터(save_data.yaml, 고른 교과만)를 넣어 내보내기·백업 → 백업 ZIP으로 되살리기로 그 교과를 되살림(다른 교과는 그대로, 바뀌는 교과의 지금 내용은 휴지통으로). 불러온 것을 브라우저에 저장하지 못하면 불러오기 전으로 되돌리고 PC 폴더에는 쓰지 않음
  - 과정 전체 백업으로 되살리기와 저장해 둔 폴더 열기는 바꾸기 전에 확인을 받고 지금 상태를 백업 파일로 먼저 내려받음. 휴지통과 작업 기록은 지금 것과 파일·폴더의 것을 합침
  - 작업 기록은 차시 id·교과 id·남긴 까닭(다시 생성 전·고치기 전·문제은행 수정 전 등)을 함께 남김. 차시 전체 기록은 5개 탭을, 탭 하나만 남긴 기록(탭 다시 생성, 탭 전체 AI 수정·컨벤션 수정 반영, 문제은행 수정, 학습 목표 추가·삭제)은 그 탭만 그 차시에 되돌림(탭이 없는 최종 평가는 본문 전체). 기록을 남긴 교과에서 그 차시를 찾지 못하면(지웠거나 다른 교과로 옮긴 차시 등) 지금 교과에 새 차시로 되살림(이번 업데이트 전의 탭 기록은 새 차시의 기본학습 칸으로). 되돌릴 때 찾지 못한 그림 자리가 차시의 그림을 덮지 않음
  - 작업 기록 한 칸에는 그 글이 쓰는 그림만 담음. 작업 기록 창은 기록 크기를 글자 수로 어림해 기록이 커도 바로 열리고, 창을 그리다 실패하면 안내를 보임. 저장해 둔 기록은 열 때 겹치거나 쓸 수 없는 id를 새로 매기고 예전 탭 기록의 쓰지 않는 그림을 덜어 냄
  - 카드의 다시 생성은 5개 탭과 그림을 모두 새로 만든다고 경고하고, 확인 창 버튼은 동작 이름(휴지통으로 옮기기, 새 목차 만들기 등)으로 보임
  - 내보내기·백업 버튼 옆에 위쪽 전체 백업 시각(그림을 담은 과정 전체 백업과 불러오기 전 자동 백업만 셈. 교과 백업 ZIP과 그림을 뺀 백업은 세지 않음. 이 브라우저에 기록이 없으면 '전체 백업 기록 없음'이라고 하고, 이번 업데이트 전에 받은 백업은 세지 않는다고 알림. 7일이 지나거나 기록이 없으면 노란색). 누르면 과정 전체 백업 ZIP을 받음. 교과 백업 ZIP 받기는 편집 중에는 지금 교과만 받음
- **화면 덜어내기**:
  - 위쪽 버튼은 내보내기·백업, 작업 기록, 설정 셋. 내보내기·백업 한 메뉴에 읽기용 내보내기(현재 차시·현재 교과), 백업 ZIP(교과·과정 전체·되살리기), PC 폴더 자동 저장이 있음. 검색 그림 저장소와 작성 규칙(컨벤션)은 설정 → 고급
  - 작업 기록과 검색 그림 저장소 창은 개요·편집기 어느 화면에서든 열림
  - 편집기의 예전 'AI 목차 생성'(교과 단위 일괄 생성 창)과 쓰이지 않던 '단원 수' 칸을 없앰. 같은 일은 AI 차시 목차 생성 → 교과 일괄 작업의 남은 차시 생성으로 함. 차시 수는 목차 생성 버튼 바로 위에 둠
  - 참고자료 탭의 '파일에서 글자 가져오기'로 PDF·PPTX·DOCX·MD·TXT·그림 파일의 글자를 참고 텍스트에 넣음(예전 일괄 생성 창의 파일 올리기를 옮김). 참고 링크는 주소만 전달되고 AI가 링크 안을 읽지 못한다고 사실대로 안내
  - 큰 참고 파일도 받음: MD·TXT는 크기와 상관없이 넣을 만큼(파일마다 앞 100,000자)만 앞에서 읽고, PDF·PPTX는 그만큼 모이면 다음 쪽·슬라이드를 읽지 않음. PDF·PPTX·DOCX는 파일 전체를 메모리에 올려 읽으므로 512MB까지, 그림은 64MB까지(4MB가 넘는 그림은 긴 변 2,400으로 줄여 JPEG로 판독을 보냄). 칸에는 파일마다 앞 100,000자까지만 넣고(교안에는 앞 8,000자, 목차에는 앞 4,000자가 쓰임) 더 길면 그렇다고 적음. 차시 참고 파일도 붙일 만큼(20,000자)만 읽음. 테스트: tests/reference-files.test.js
  - 화면 용어를 교과·차시·최종 평가·작업 기록으로 맞춤(메인 퀘스트·레벨테스트·발급·모듈·히스토리·캐시 보관함·미연결 등). AI에 보내는 프롬프트 문장은 그대로
- **남이 준 파일과 실수에서 지키기**:
  - 백업 ZIP·PC 폴더에서 되살린 상태를 믿지 않음(sanitizeState + data-safety.js 검사): 교과 id는 안전한 글자만, 차시 id는 숫자로(화면 코드에 따옴표 없이 들어감. 교과 안에서만 겹치지 않게 하고 새 id는 가장 큰 id 다음 수), 글 값은 문자열로, 참고 링크는 http(s)만. 백업의 휴지통·작업 기록은 모양이 맞는 항목만 받고(휴지통의 지운 날짜는 ISO 날짜로 맞춤. 못 읽거나 하루 넘게 미래면 지금 시각. 휴지통 항목의 이름은 글로, 교과의 차시 목록은 배열로 맞춤. 작업 기록은 칸마다 검사), 휴지통에서 되살리는 교과·차시도 같은 검사를 거침. 차시와 최종 평가의 안쪽도 검사함: 그림 키는 영문·숫자·_·- 80자까지, 그림 값은 data:image/형식;base64 글이나 따로 담은 그림의 이름(teacher-image:…)만(형식에 대문자·빈칸·매개변수가 붙어 저장된 그림은 data:image/형식;base64로 고쳐 받음. Higgsfield 그림은 처음부터 형식만 남겨 저장), 탭 글·본문·교수안 글은 문자열만, 목록 칸은 배열만이고 그 줄도 맞춤(학습 목표·툴의 이름과 버전·선행 차시의 제목·변경 이력의 시각과 내용은 글, 선행 차시 id는 글이나 숫자. 카테고리·검수 상태도 글. 바른 값은 그대로 둠). 작업 기록을 차시에 되돌릴 때 넣는 그림도 같은 규칙. 그림 id·차시 제목을 정규식에 그대로 넣지 않음(정해 둔 모양으로 찾아 글자 그대로 견줌. 차시 화면·원문 칸 나란히 보기·내보내기의 그림 넣기는 그림 키 모양 하나로 찾아 그림 목록에서 꺼내고, 그림 지우기는 마크다운 그림 모양 하나로 찾아 주소가 꼭 같은 것만 지움). 과정명·차시 설명·참고 링크·폴더 이름·다이어그램 실패 표시·검색어·창 제목은 escapeHtml로 화면에 넣음. 악성 백업 테스트: tests/data-safety.test.js
  - 백업 ZIP·PC 폴더로 되살릴 때는 새 상태를 다 만들고 검사한 뒤 한 번에 바꿈(도중에 멈추면 지금 작업은 그대로. 되살릴 교과가 없는 파일·폴더는 묻지 않고 멈춤). 백업 ZIP으로 바꾼 상태를 브라우저에 저장하지 못하면 바꾸기 전 상태로 되돌리고 그 상태를 다시 저장함(그것도 못 하면 Ctrl+S로 다시 저장하라고 알림. Ctrl+S는 브라우저에 저장했을 때만 '저장했습니다'라고 함. 읽지 못한 저장본 대신 열던 중이었으면 읽지 못한 창으로 돌아감). 이어진 PC 폴더에는 바꾼 상태를 브라우저에 저장한 뒤에만 씀(되돌린 파일의 작업이 폴더에 남지 않게). 되살려 저장한 뒤 화면을 다시 그리다 실패해도 되살리지 못했다고 하지 않음. 폴더의 저장본을 풀지 못하면 교과가 없는 것과 다르게 알림. 과정 전체 백업의 차시 MD는 내보낸 교과의 차시 가운데 제목이 꼭 같은 것에만 맞춤(메모장에서 고친 CRLF MD도). 테스트: tests/import-restore.test.js
  - 시작할 때 이 브라우저에 저장된 작업을 읽지 못하면 예시 과정으로 덮어쓰지 않음: 저장과 PC 폴더 다시 잇기를 멈추고, 뒤 화면을 막은 창에서 다시 읽기·백업 ZIP으로 되살리기·저장해 둔 폴더 열기·읽지 못한 저장본 내려받기(저장본을 읽어 오기는 했을 때만. 고치지 않은 그대로 파일로 받으며 앱에서 바로 되살리지는 못함)·새로 시작 가운데 고르게 함. 되살리거나 새로 시작하기 직전에 읽지 못한 저장본을 IndexedDB의 다른 이름(`agent_curriculum_v4_7:읽지못함:시각`)으로 한 벌 옮겨 두고(한 창에서 한 번만 옮기고 새것 셋만 남김. 백업 ZIP 되살리기를 저장하지 못해 읽지 못한 창으로 돌아가면 저장본이 제자리에 그대로라 그 사본은 지우고, 오래된 사본은 되살린 것을 저장한 뒤에야 정리함. 옮기지 못해도 계속함. 꺼낼 때는 개발자 도구). '새로 시작'·백업 ZIP으로 되살리기·저장해 둔 폴더 열기는 바꾸기 직전에 저장본을 다시 읽어 이제 열 수 있으면 바꾸지 않고 '다시 읽기'로 열게 함. 새로 시작은 예전 PC 폴더 연결도 잊음(폴더 파일은 그대로). 예전 localStorage 저장본은 IndexedDB로 옮긴 뒤에만 지움
  - 작업이 아주 커도 브라우저에 저장함(state.js writeBrowserState): 크롬은 IndexedDB 값 하나를 127MiB까지만 받아, 그림이 많은 교안 HTML을 불러온 교과처럼 큰 작업은 값으로 저장하지 못함. 저장할 값의 어림(그림 글은 한 글자 1바이트, 다른 글은 2바이트)이 100MB를 넘거나 브라우저가 값이 너무 크다고 거절하면(한 번 거절되면 그 창에서는 처음부터) 작업 전체를 JSON 파일(Blob. IndexedDB가 따로 저장하고 그 한도에 세지 않음)로 저장하고, 작은 작업은 예전처럼 값 그대로 저장함. 시작할 때 JSON 파일 저장본은 그림 글을 떼어 둔 조각 읽기로 풀고(import-stream.js. 못 하면 파일 전체로), 풀지 못하면 덮어쓰지 않고 읽지 못한 창으로 막으며 내려받기는 그 파일 그대로 줌. 테스트: tests/import-restore.test.js
  - AI 차시 목차 생성 중 다른 교과를 열어도 새 목차는 시작한 교과에만 들어감. 최종 평가 만들기·카드의 교안 생성도 끝날 때 다른 교과를 보고 있으면 그 화면에 그리지 않고(최종 평가는 어느 교과에 만들었는지 알림), 교안 탭 모두 다시 만들기는 다른 교과로 옮기면 그 교과의 같은 번호 차시·최종 평가를 다시 만들지 않고 멈춤. 다른 교과의 차시를 그린 원문 칸의 글은 지금 교과의 차시에 넣지 않음
  - PC 폴더에 저장 시작할 때 그 폴더에 저장본이 있으면 묻고, 덮어쓰면 기존 파일은 save_data_이전_날짜.yaml로 남김(같은 분에 또 남기면 _2, _3을 붙여 앞 사본을 덮지 않음)
  - PC 폴더 자동 저장이 실패하거나(그림이 많음, 디스크 부족 등) 멈추면(브라우저를 다시 엶, 쓰기 권한이 풀림, 저장본이 다른 PC·브라우저에서 바뀜, 폴더가 사라짐) 머리줄 아래 띠로 알림
  - 과정 전체 백업 ZIP은 개요 화면에서도 받음(파일 이름: 과정명_과정전체백업_날짜). 작업 기록은 200개까지 두고 오래된 것부터 지움(지울 때 화면에 알림. 휴지통의 지운 차시도 100개를 넘겨 지우면 알림). 백업 ZIP·PC 폴더를 불러와 기록을 합칠 때는 이 브라우저의 기록을 먼저 남기고, 같은 기록은 한 번만, 미래 시각으로 적힌 기록은 지금 시각 아래로 맞춤. 칸이 모자라 넣지 못한 기록 수는 마침 알림에 적음(백업 ZIP의 것은 그 파일에 남음. PC 폴더의 것은 이어지는 폴더 저장에서 save_data.yaml에서는 빠지지만, 폴더를 열 때 남긴 사본 save_data_이전_날짜.yaml(예전 save_data.json만 있는 폴더는 사본을 만들지 않고, 고치지 않는 그 save_data.json)에 남고 마침 알림에 그 파일 이름을 적음)
  - 휴지통의 완전 삭제는 먼저 묻고, 이름이 겹치는 교과를 되살려도 차시 카드가 열림. 복원·완전 삭제는 누른 줄의 항목에만 함(목록을 다시 그리기 전에 두 번 눌러도 당겨진 다음 항목을 되살리거나 지우지 않음)

- **그림 다시 보내기와 한도**: 그림 쪽 호출(그림 모델·그림 검색어·판정·SVG 삽화)은 한 번만 다시 보냄. Gemini가 한도 0·하루 한도로 답한 429는 글·그림 모두 다시 보내지 않음(Claude의 429는 Claude SDK가 다시 보냄. 남은 차시 생성은 실패한 차시를 30초 뒤 한 번 더 해 봄(다시 보내도 같은 오류인 400 요청 오류 등은 다시 해 보지 않고 다음 차시로 넘어감). 하루 한도·한도 0·키·잔액·권한·모델 문제나 인터넷 끊김이면 다시 해 보지 않고 일괄 생성을 멈추고 까닭을 보임. 진행 막대의 다른 생성이 도는 동안에는 시작하지 않음. '이미 만든 내용도 모두 다시 만들기'로 비운 차시에 탭을 하나도 만들지 못하면 지우기 전 내용으로 되돌리고 휴지통 사본을 뺌). 한 작업(전체 생성·남은 차시 생성·일괄 작업) 안에서 그림 모델이 모두 막히면 더 부르지 않고(검색 키가 있으면 교안 그림은 검색만) 그림 자리를 남긴 뒤 한 번 알리고, 작업이 끝날 때 남긴 수(교안 그림 자리, 교수안 슬라이드 그림)와 남긴 곳에 맞는 할 일을 보임. 중지하면 그리던 그림 호출과 다시 보내려고 기다리던 호출을 끊음(받고 있는 교안 단락은 끝까지 받음. 글 모델이 Claude면 교안 단락을 다시 보내려고 기다리는 동안은 Claude SDK가 맡아 끊지 못함)
  - 그림을 못 만든 자리(이미지 영역·이미지 확보 실패)의 '다시 검색'은 새 그림을 만들어 그 자리에 넣음(원문에서 그 자리를 찾지 못하면 만들지 않고 알림)
  - 일괄 이미지 찾기·콘텐츠 정리는 그리는 동안 차시가 지워졌거나 백업·PC 폴더를 불러와 바뀌면 옛 차시에 넣지도 화면에 그리지도 않음(일괄 이미지 찾기는 멈추고, 콘텐츠 정리는 지운 차시를 건너뛰며 교과째 바뀌면 멈춤). 끝 알림은 지금 데이터에 넣은 그림만 셈. 저장하지 못하면(저장 공간 부족 등) 그림을 더 부르지 않고 멈춤
- **백업 그림 담기 고르기**(data-safety.js): 내보내기·백업 메뉴의 '그림 담기'에서 함께 / 따로·가볍게 / 빼기를 고름. 함께·따로·가볍게는 이 브라우저에 기억하고(처음은 함께) 백업 ZIP과 PC 폴더 자동 저장에 같이 적용
  - 함께: 예전처럼 그림을 save_data.yaml 안에 담음. 그림이 많아 한 파일에 담지 못하면(글자 수·메모리 한도) 저절로 따로·가볍게로 다시 만들고 알림. 그 뒤로는 따로·가볍게로 기억. 따로·가볍게로도 담지 못하면 방식은 바꾸지 않고 크기 안내만 보임
  - 따로·가볍게: 그림을 `그림/<키>.<확장자>` 파일로 빼고 save_data.yaml에는 `teacher-image:<키>`만 남김. 같은 그림은 한 번만 담고, PC 폴더에는 이미 있는 그림 파일을 다시 쓰지 않음. 되살리면 그림도 돌아옴(백업 정보에 imageMode가 남음)
  - 빼기: 기억하지 않음. 메뉴를 연 채 바로 받는 백업 ZIP 하나에만 쓰고, 그 백업을 받기 시작하거나 메뉴 밖을 누르면 풀림(머리줄 백업 시각·교과 목록 ZIP 버튼은 빼기를 쓰지 않음). 그 파일의 save_data.yaml에서 그림을 빼고 파일 이름 끝에 `_그림없음`을 붙이며 위쪽 전체 백업 시각에 세지 않음. 읽기용 파일(교과 백업의 교안.html·images, 과정 전체 백업의 첨부파일)에서는 그림을 빼지 않음. 백업 ZIP으로 되살리면 그림 자리가 비고(과정 전체 백업은 받을 때 열려 있던 교과의 첨부파일 그림이 그 교과 차시에 돌아올 수 있음) 뺀 그림은 다시 채워지지 않음(일괄 이미지 찾기는 아직 채우지 않은 그림 태그만 채움. 자동으로 넣은 그림은 그림마다 '다시 찾기'·'다시 생성'으로 새로 만들 수 있고, 붙여 넣은 그림은 다시 넣어야 함). 예전에 기억된 빼기는 따로·가볍게로 읽음
  - PC 폴더 자동 저장과 불러오기 전 자동 백업은 빼기를 쓰지 않음. 불러오기 전 자동 백업은 고른 방식과 상관없이 늘 따로·가볍게로 담고, 받지 못하면 까닭을 알린 뒤 백업 없이 계속할지 물음
  - 그림을 뺀 백업 ZIP이나 폴더를 불러오면 확인 창에 되살리기용 정보에 그림이 담기지 않았다는 것과 빈칸이 될 지금 그림 수를 보임(교과 백업이면 안의 읽기용 교안.html·그림 파일로는 되살리지 않는다는 것도)
- **PC 폴더 열기·저장**(state.js, data-safety.js):
  - 저장해 둔 폴더 열기는 저장본이 가리키는 그림만 '그림' 폴더에서 파일마다 따로 읽음. 그림 파일은 내용이 이름(내용 해시와 길이)과 맞을 때만 받음(복사가 끊겨 짧아졌거나 뒤가 빈 파일은 받지 않음. AVIF는 .avif로 쓰고 그대로 읽으며, 예전에 .png로 쓴 AVIF도 내용으로 가려 원래 형식으로 되살림(백업 ZIP도 같은 규칙). 확장자가 없는 형식이라 .png로 쓴 그림 가운데 image/jpg·image/bmp·image/avif 말고는 내용을 가리지 못해 길이만 봄). 찾지 못했거나 읽지 못했거나 망가진 그림이 있으면 확인 창에 "그림 N장 중 M장"으로 알리고(작업 기록·휴지통의 그림도 셈), 취소하면 아무것도 바뀌지 않음
  - 찾지 못했거나 망가진 그림은 `teacher-image:<키>` 참조를 그대로 둠(마침 알림에도 같은 수를 적음). 화면과 내보내기에서는 빈 그림으로 보이고 다음 저장도 참조를 지우지 않아, 성한 그림 파일을 '그림' 폴더에 채운 뒤 다시 열면 돌아옴(이 브라우저에 합쳐 둔 작업 기록·휴지통의 그림도)
  - 폴더를 열면 첫 저장 전에 그 폴더의 save_data.yaml을 save_data_이전_날짜.yaml로 남김(못 남기면 열지 않음. 열 때마다 하나씩 늘어나니 필요 없으면 지워도 됨). 휴지통·작업 기록은 지금 것과 폴더 것을 합치고(칸이 모자라 넣지 못한 폴더의 기록은 그 사본에, 예전 save_data.json만 있는 폴더는 그 파일에 남는다고 알림), 그림 담기를 그 폴더의 방식(함께·따로·가볍게)에 맞춤. 예전 save_data.json만 있는 폴더도 열림(그 파일은 고치지 않음)
  - 새로고침 뒤 이어 쓸 폴더는 연 작업을 브라우저에 저장한 뒤에야 기억하고, 그 전에 앞서 기억한 폴더는 잊음(그 사이 창이 닫혀도 브라우저에 남은 옛 작업이 어느 폴더도 덮지 않음). 브라우저 저장이 실패하면 기억하지 않고, 새로고침 뒤에는 '저장해 둔 폴더 열기'로 다시 열라고 마침 알림에 적음
  - 폴더 자동 저장은 한 번에 하나씩 돌고, 도는 동안 들어온 저장은 하나로 합쳐 끝난 뒤 최신 상태로 씀. 그림 파일을 먼저 쓰고 save_data.yaml을 씀. 앱을 연 뒤 한 번 쓰거나 크기를 확인한 그림 파일과, 내용이 그대로인 첨부 그림·MD는 다시 쓰지 않음(이름 규칙에 차시 번호가 없어 두 차시가 한 MD에 쓰면 예전처럼 마지막 차시가 남음). 차시 MD의 그림 자리는 그림 이름으로 정규식을 만들지 않고 바꿈. 과정·교과 폴더와 차시 MD·첨부 그림 파일 이름의 경로 글자('/', '\' 등)는 '_'로 바꾸고, 과정·교과 이름이 비거나 점뿐이면 새_교안프로젝트·교과_<교과 id> 폴더에 씀(불러온 파일의 그런 이름에 폴더 저장이 매번 실패하지 않게)
  - 앱은 폴더의 파일을 지우지 않음. 다시 만들거나 지운 그림의 파일도 '그림'·'첨부파일' 폴더에 남으므로, 다른 사람과 나눌 때는 백업 ZIP을 씀
  - 쓰기 권한이 풀리면 권한 창을 띄우지 않고 자동 저장을 멈춘 뒤 머리줄·띠의 '다시 연결'로 물음. 다시 연결하면 바로 저장함. 이 브라우저가 마지막으로 저장한 뒤 폴더의 저장본이 다른 PC·브라우저에서 바뀌었으면 덮어쓰기 전에 묻고 기존 저장본은 사본으로 남김(새로고침 때 권한이 남아 있어도 멈추고 '다시 연결'에서 물음). 저장본을 읽지 못하면 사본을 남길 수 없어 덮어쓰지 않고 자동 저장을 멈춘 채 둠(폴더 파일을 확인한 뒤 '다시 연결'을 다시 누르거나 '빈 폴더에 저장 시작'으로 다른 폴더를 고름). 브라우저 저장이 실패한 동안 폴더에만 저장된 작업이 있으면(브라우저 저장 공간 부족 등) 새로고침 뒤 폴더에 잇지 않고 '저장해 둔 폴더 열기'로 되찾으라고 알리며, '다시 연결'은 폴더에 더 새 작업이 있다고 먼저 묻고 사본을 남김. 이 브라우저에 남은 마지막 저장 기록(크기·고친 시각)이 이 폴더 것이 아니면(이 기능이 생기기 전에 연결했거나, 그 뒤 다른 폴더에 저장했거나, 저장이 한 번도 끝나지 않음) 바뀌었는지 알 수 없어 묻지 않고 씀
  - 참고자료 칸은 입력이 1초 멈추거나 칸을 벗어나면 저장하고, 창이 가려지거나 닫힐 때는 기다리던 저장을 바로 시작함(글자마다 과정 전체를 저장하지 않음). 테스트: tests/folder-sync.test.js
- **문제은행**: 학습 목표×밴드 분포, 문항 검수, AI 문항 생성, 문항 편집, CSV 저장
